# ペルソナと自我の計画

Partner の個性を、プロファイル（ペルソナ）と D1（自我）の 2 層に分けて持つための Goal / Epic / Issue。Epic 名は他の計画と区別するため SE1〜SE3 とする。`docs/design/persona.md` の「Yunomi-specific identity」を、会話例と持ちネタにまで広げる計画である。

## ペルソナと自我

ペルソナは、その Partner がどういう人であるべきかを定めた設計である。自我は、Yunomi で持ち主と過ごした結果、どういう人になったかの記録である。

| | ペルソナ | 自我 |
| --- | --- | --- |
| 置き場所 | `partners/<id>/`（`profile.yaml`、`identity/`、`examples.yaml`） | D1 |
| 既にあるもの | 人格本文、values、興味・意見の初期値、口調の会話例 | state、関係、学習した興味・意見、記憶、未解決の話題 |
| この計画で足すもの | なし | 拾った会話例、持ちネタ |
| 変わる契機 | キャラクターの設計を直すとき（PR とデプロイ） | 会話のたび |
| 公開 | リポジトリに載る | 載らない |

振る舞いへの指摘は、まず自我の側で吸収する。人格本文や指示に規則を足すと、プロンプトが指摘の数に比例して伸び、規則の多さそのものが返事を堅く文字どおりにする。ペルソナを直すのは、キャラクターの設計がずれているときに限る。

ペルソナは自我の上限としても働く。興味の score が baseline から ±0.3 までしか動かないのと同じく、自我がどれだけ育ってもペルソナから外れすぎないよう縛る。会話例であれば、拾った例はペルソナの会話例と並べて選ぶ候補にとどまり、人格本文や values を書き換えない。

読むときは、興味・意見の `resolveInterests(profile, rows)` と同じく、プロファイルの値と D1 の行を合わせる。ペルソナの会話例を D1 に取り込むことはしない。`examples.yaml` を直しても D1 の移行は要らない。

## Goal

持ち主が気に入った返事にリアクションを付けると、その返事が以後の会話例の候補になる。返事のたびに、届いた発言に近い例がペルソナと自我の両方から選ばれ、プロンプトに入る件数は今と同じ 4 件のままである。持ち主は PR を書かずに、使いながら口調を育てられる。

## Epic 一覧

| Epic | ユーザーから見える成果 | 依存 |
| --- | --- | --- |
| SE1 | 返事にリアクションを付けると、その発言と返事が会話例として D1 に溜まる | なし |
| SE2 | 届いた発言に近い会話例が、ペルソナと自我の両方から選ばれる | SE1 の型 |
| SE3 | 持ちネタが会話から溜まり、cooldown 付きで使われる | SE1 |

### SE1. 会話例を拾う

- 技術範囲: Gateway がゆかりの発言へのリアクションを Worker に送る Envelope。Worker は決まった絵文字の付け外しを受け、直前の相手の発言と返事（連投はまとめる）を会話例の行として D1 に書く。外されたら行を消す。`ykm` に一覧と削除を足す。
- 非ゴール: 避ける例（よくない返事）の収集、自動での例の生成。
- Done: リアクションの Envelope から、会話例の行が書かれ、外すと消えることがテストで確かめられる。

### SE2. 近い例を選ぶ

- 技術範囲: `selectExamples` を、場面の無作為な選択から、届いた発言との近さで選ぶ方式に変える。候補はペルソナの会話例と D1 の行を合わせたもの。同じ例ばかり選ばれないよう、選ばれた回数か最後に選ばれた時刻で間引く。
- 非ゴール: 例の自動要約や書き換え。
- Done: 同じ入力から同じ例が選ばれ、近い発言の例が優先されることがテストで確かめられる。プロンプトに入る件数は `EXAMPLE_COUNT` のまま変わらない。

### SE3. 持ちネタ

- 技術範囲: `profile.yaml` の `recurring_jokes` を初期値とし、会話から生まれた持ちネタを D1 に溜める。cooldown は今の `recurring_jokes` と同じ仕組みで扱う。
- Done: 未定（SE1・SE2 のあとで詰める）。

## 未決事項

要判断: 拾うリアクション。どの絵文字にするか、持ち主以外のリアクションを数えるか。

要判断: 近さの測り方。Workers AI の埋め込みと Vectorize を使うか、語の重なりのような軽い方法で始めるか。例が数百件までなら、D1 の行を全件読んで Worker の中で比べても足りる。

要判断: 消し方。リアクションを外したら消すだけにするか、`ykm` からも消せるようにするか。

要判断: 自分の返事を手本にし続けると、同じ言い回しに寄っていく。間引きのほかに、拾った例の件数に上限を設けるか。
